## Blocker 1 — Network egress to brand9signs.com is blocked in this environment

Every `WebFetch` attempt against `brand9signs.com` (homepage, `/product-category/
marketing-branding/`, and a known-indexed page `/sign-company-orange-park-fl/`)
failed immediately with `EGRESS_BLOCKED` from the network egress proxy — not a
site-side error, a session/environment-level network policy block. This means
none of the following could be directly verified this run:
- Homepage load / console errors / motion film embed rendering
- Category page tile row, product cards, Motion Films block
- 5 random product pages (HTTP 200, image, price)
- OG image rendering for the homepage
- Yoast meta fields on any page

## Blocker 2 — The check list assumes an architecture the live site no longer has

Per the repo's `b9-site-deploy` skill (verified 2026-08-08 / 2026-08-11, marked
authoritative): **brand9signs.com is a static HTML build on DreamHost (~357 pages,
folder-per-slug), not WordPress.** The WordPress/WooCommerce/Yoast backend is a
dead legacy system that no longer serves the live site (`/wp-json/` returns the
static site's custom 404).

That means, independent of the egress block:
- `/product-category/marketing-branding/` is a WooCommerce URL pattern — this
  site has no product categories, product cards, or prices in that sense.
- "Yoast SEO meta on the Motion Films product page" — there is no Yoast plugin
  and no "Motion Films product page" in the current static build; Yoast checks
  don't apply.
- The site's actual content model is answer pages (homebuilder/sign-company
  city and vertical pages) with hand-authored `<title>`/meta description and
  FAQPage/LocalBusiness JSON-LD, not Yoast-managed fields.
