## Root Cause Assessment

| Signal | Interpretation |
|--------|----------------|
| All URLs → 403 (not 404 or 5xx) | Server is alive and responding |
| Consistent site-wide 403 | WAF (Cloudflare/similar) blocking automated user-agents |
| Site appears in Google index | Googlebot is whitelisted; real browsers likely served normally |
| No downtime reports in public monitoring tools | Likely not a true outage |

**Most probable cause:** The site runs a bot-protection policy (e.g., Cloudflare "I'm Under Attack" mode, Bot Fight Mode, or custom firewall rules) that returns 403 to cloud-hosted automated HTTP clients. This is a **monitoring gap**, not necessarily a live user-facing outage — but it means this health-check pipeline **cannot verify any of the 6 required checks**.

---

## Recommendations

1. **Whitelist the monitoring agent's IP range** in Cloudflare/hosting WAF rules, or configure a dedicated monitoring token/header.
2. **Add uptime robot or Pingdom** (real-browser checks with real IP diversity) as a parallel monitor that bypasses this restriction.
3. Until whitelisted, this pipeline will always report 🔴 RED, making it unreliable as a health signal.
