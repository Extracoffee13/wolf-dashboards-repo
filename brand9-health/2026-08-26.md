## Second, unresolved issue: architecture mismatch

This task was written assuming a WordPress/WooCommerce site (Yoast SEO
meta, `wp-content` OG image path, "product pages" with prices, a
`product-category` archive). That contradicts this repo's own
`b9-site-deploy` skill (verified 2026-08-08), which states plainly:

> "brand9signs.com is a static HTML build on DreamHost, deployed by Hermes.
> It is NOT WordPress." — wp-admin/wp-json is described as a dead legacy
> backend no longer serving the live site.

However, `WebSearch` results for `site:brand9signs.com` returned indexed
URLs that look exactly like live WooCommerce/WordPress output:
- `https://brand9signs.com/product-category/marketing-branding/` —
  indexed title "**Marketing & Branding Archives** | Brand 9 Signs" (the
  "Archives" suffix is WordPress/WooCommerce taxonomy-archive convention,
  typically Yoast-generated)
- `https://brand9signs.com/product-category/school-branding/`
- Individual `/product/custom-restaurant-signs/`, `/product/monument-signs/`,
  `/product/dimensional-sign-letters/`, `/product/corporate-wall-branding/`
  pages

This is a real conflict, not just stale index noise I can wave away — it
could mean the `b9-site-deploy` skill is out of date, or it could mean the
search index is showing pre-rebuild cached titles that no longer reflect
the live static site. **I cannot tell which from here**, because I cannot
fetch the URLs directly in this environment.
