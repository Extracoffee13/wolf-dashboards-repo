## Root Cause: WAF `host_not_allowed` Block

```
HTTP/2 403
x-deny-reason: host_not_allowed
content-type: text/plain
```

This header means the hosting provider has an **IP allowlist** or country/ASN block that rejects requests from cloud compute IPs (AWS, GCP, Azure, etc.). This is the same class of block that prevents automated health monitors, uptime bots, and CMS update checkers from functioning.

**Recommendation:** Allowlist the monitoring IP(s) at the hosting/CDN level, or use a residential-IP proxy for automated health checks. Alternatively, configure a WordPress plugin (e.g., WP Cron or Heartbeat) to push status pings outbound rather than polling inbound.
