**Important caveat:** This is not a confirmed site outage. The 🔴 is raised because
the monitoring session itself was unable to perform the required checks, not

Treat this as "unverified / instrumentation failure," and re-run the audit from

## Root cause: outbound network access blocked in this session

`WebFetch` returned `HTTP 403 Forbidden` for **every** URL tested, including a
neutral control (`https://example.com`), not just `brand9signs.com`. Direct
`curl` through the session's egress proxy also failed the same way (`CONNECT
tunnel failed, response 403`). The proxy status endpoint confirms this is a
policy-level denial at the gateway, not a site-side error:

```
recentRelayFailures:
  - host: brand9signs.com:443 → connect_rejected (403, policy denial)
  - host: example.com:443     → connect_rejected (403, policy denial)
```

Since the control URL failed identically, this session had no working
outbound HTTP fetch tool at all today. `WebSearch` (a separate, non-proxied
backend) did work and was used to gather indirect/secondary signal only —
it cannot check console errors, HTTP status codes, embed rendering, image
presence, Yoast meta fields, or OG image rendering, all of which require an
actual page fetch/render.
