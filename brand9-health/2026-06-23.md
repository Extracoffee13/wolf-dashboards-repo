## Root Cause: Cloudflare WAF — HTTP 403

The entire monitoring run was degraded by Cloudflare blocking the `WebFetch` tool's requests. This is **not** a site outage, but it is a monitoring blind spot. The 403 appears at the Cloudflare edge (not the origin), and is most likely triggered by:

- **Bot Fight Mode** (blocks non-browser user-agents)
- A WAF managed rule matching the request signature
- No trusted IP allowlist for the monitoring agent

**Recommended action:** Add the monitoring agent's egress IP(s) to a Cloudflare IP Access Rule, or configure a Bypass WAF rule for the health-check user-agent. Alternatively, set up a WordPress heartbeat endpoint (e.g., a simple `/health` route) that responds to a shared secret token.
