## Root Cause Assessment

The `x-deny-reason: host_not_allowed` header is characteristic of a CDN or reverse-proxy layer (possibly Fastly, WP Engine Edge, or a custom Google Cloud Load Balancer rule) that has an explicit allowlist of accepted Host values or origin IP ranges. Possible causes:

1. **WAF misconfiguration** — a recent firewall rule or geo-IP block accidentally set to deny all
2. **Maintenance / origin lockdown** — intentional lockdown while site is being updated
3. **Hosting migration in progress** — DNS/CDN reconfiguration mid-flight
4. **DDoS protection triggered** — security vendor put the site in lockdown mode

The site is NOT completely dead — SSL is valid, DNS resolves, and Google's cached index shows content. The block is at the request-authorization layer.

---

## Recommended Actions

1. **Immediate:** Check CDN/WAF dashboard (WP Engine, Cloudflare, or GCP Load Balancer) for recently changed access rules
2. **Verify:** Confirm whether the site loads in a standard browser from an office network — if yes, the block is IP-range specific (monitoring IPs blocked)
3. **If browser also fails:** Roll back any CDN configuration changes from the past 24–48h
4. **Contact host:** If using managed WordPress hosting, open a P1 support ticket referencing `host_not_allowed` header
