# Brand 9 Site Health Report — 2026-07-30

## Overall status: 🔴 RED (audit blocked — not a confirmed site outage)

This run could not reach `brand9signs.com` at all. Every outbound request to the
domain was rejected at the session's network egress layer before it ever left
this container, so none of the six checks below could be performed against the
live site. This is being reported as RED because the audit's job — verify the
site is healthy — could not be discharged, not because the site itself was
observed to be down.

## What happened

- `WebFetch` on `https://brand9signs.com` and
  `https://brand9signs.com/product-category/marketing-branding/` both returned
  a bare `403 Forbidden` with no response body.
- A direct `curl` to the same host failed to connect at all (exit 56).
- The agent egress proxy status endpoint
  (`$HTTPS_PROXY/__agentproxy/status`) confirms the cause:
  ```
  recentRelayFailures:
    kind: connect_rejected
    detail: "gateway answered 403 to CONNECT (policy denial or upstream failure)"
    host: brand9signs.com:443
  ```
  Per the proxy's own guidance, a 403 at the CONNECT stage means the
  destination host is not on this session's egress allowlist — it should be
  reported, not retried or routed around. So this run did not retry beyond
  confirming the block was host-level and not path-specific.
- `WebSearch` (a different, allowed egress path) still worked and confirms the
  domain is indexed and resolves fine from the public internet — e.g. it
  surfaced `brand9signs.com/sign-company-orange-park-fl/` and
  `brand9signs.com/jacksonville-sign-company/` as live, indexed pages. This is
  a signal (not proof) that the site itself is reachable from the outside;
  the failure is specific to this session's network policy, not necessarily
  the site.
