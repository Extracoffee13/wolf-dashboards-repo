## Important correction to the check list itself

Per the repo's `b9-site-deploy` skill (verified 2026-08-08, authoritative):
**brand9signs.com is a static HTML build on DreamHost, deployed by Hermes — it is NOT
WordPress.** The `wp-admin`/WordPress backend is a dead legacy system that no longer
serves the live site. That means:

- Check #4 ("Verify Yoast SEO meta … no yoast-placeholder leakage") targets a plugin
  that doesn't run on the live site. This check should be replaced with a direct check
  of the static page's `<title>`, `<meta name="description">`, and JSON-LD, read from
  the deployed HTML/served page — not from a WordPress admin or REST API.
- The site also sits behind an `sgcaptcha` bot-challenge that returns a fake ~181-byte
  202 interstitial to plain HTTP fetches (curl, urllib, and by extension tools like
  `WebFetch`) instead of the real page — per `b9-site-health-sentinel`. Even if egress
  were not blocked, a raw fetch would likely have reported false negatives (looking
  "down" when it isn't) rather than real content.
- The task description's product-category/Marketing-Branding language (tiles, product
  cards, "Motion Films" as a WooCommerce-style product) doesn't match the documented
  static-site page inventory either — worth confirming this checklist still matches the
  live site's actual structure.
