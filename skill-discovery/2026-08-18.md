## Candidates (score ≥ 3)

### 1. Agent Plugins 1.0.0 — open packaging standard for skills + MCP servers
- **Source:** https://vercel.com/blog/introducing-agent-plugins
- **Published:** 2026-08-06 (jointly by Amazon/AWS, Anysphere/Cursor, Microsoft, OpenAI, Vercel; Google joined as core maintainer same day)
- **Pitch:** A single package format that bundles Agent Skills + MCP servers into one directory so the same plugin installs into VS Code, Copilot, Cursor, ChatGPT, Kiro, and (via the CLI's translation layer) Claude Code — worth watching as a way to package and redistribute Construct-internal skills across tools instead of hand-copying them per client.
- **Score:** 4 — new capability the team would touch weekly if we start packaging our own skills this way; Anthropic itself is not a coalition member, so treat as an emerging convention, not a dependency, until Claude Code's native support matures.
- **Suggested owner:** WOLF

### 2. Google Analytics MCP Server (official, Google-managed)
- **Source:** https://developers.google.com/analytics/devguides/MCP
- **Published:** listed among Google's ~50 official MCP servers; most recently indexed mid-2026, still the only *official* GA4 connector (no official GSC equivalent exists yet)
- **Pitch:** First-party GA4 MCP server that lets an agent query Analytics data directly instead of going through custom API scripting — a drop-in data source for the daily GSC/GA "creative abrasion" loop.
- **Score:** 4 — direct weekly use for the B9 visibility/abrasion pull once wired to the existing service-account credentials.
- **Suggested owner:** Keystone

### 3. Autodesk Revit Public MCP Server (Technical Preview)
- **Source:** https://www.autodesk.com/blogs/aec/2026/06/17/revit-public-mcp-server/
- **Published:** 2026-06-17 (Tech Preview, actively evolving; ships as a Revit 2027 addon via accounts.autodesk.com)
- **Pitch:** Autodesk's own, officially supported MCP server for Revit — a sanctioned alternative/complement to the custom APS Design Automation AppBundle path HyperCube/STRUO currently runs by hand.
- **Score:** 4 — could reduce the debugging burden documented in `ans-cloudrevit-appbundle` once it covers our workflows (model creation, IFC export), but it's still Tech Preview and Revit-2027-only, so it's not a swap-in yet.
- **Suggested owner:** Architect

### 4. Blender MCP Server (official, blender.org)
- **Source:** https://www.blender.org/lab/mcp-server/
- **Published:** ongoing lab project under Blender Projects; no single dated release this cycle
- **Pitch:** Official Blender-maintained MCP server exposing Blender's Python API over MCP — a more maintained alternative to whatever ad hoc scripting backs the headless Blender/Cycles BlenderKit render pipeline.
- **Score:** 3 — niche (only touches the HyperCube render path) but useful if it stabilizes past lab status.
- **Suggested owner:** Architect

### 5. @mcpskillsio/server ("MCPSkills" pre-install trust layer)
- **Source:** https://www.npmjs.com/package/@mcpskillsio/server
- **Published:** v2.5.2, ~2026-08-16
- **Pitch:** A pre-install vetting/trust layer for MCP servers, skills, and npm packages — scans GitHub repos, npm packages, Smithery URLs, and OpenClaw skills before they're trusted, which is exactly the kind of gate this discovery sweep should be feeding candidates through before adoption.
- **Score:** 3 — low weekly usage on its own, but relevant as process tooling for vetting future candidates from this same report.
- **Suggested owner:** Sentinel
