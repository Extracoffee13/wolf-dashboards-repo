## Candidates (score ≥ 3)

### 1. 3dsmax-mcp — score 4
- **Source:** https://github.com/cl0nazepamm/3dsmax-mcp
- **Pitch:** A native MCP server bridging Claude directly into a running 3ds Max session (151 tools — scene reads, materials, modifiers, controllers, viewport capture, procedural graphs, render triggers) instead of driving Max through a MaxScript-file-drop job queue.
- **Relevance:** VironBox's current render-node pipeline (`vironbox-render-node` skill) is built around a fragile "scp a .ms file into a watched folder" pattern forced by the trial-license no-headless constraint. A real MCP bridge into the GUI session would let an agent issue structured scene/material/camera calls directly and read back state, closing a lot of the MaxScript landmines that skill documents. Not a full drop-in (still requires the interactive GUI session and hasn't been verified against the current Arnold/trial-license setup) — worth a spike, not an immediate swap.
- **Suggested owner:** Architect

### 2. GSC/GA MCP servers patched for MCP SDK 2.0.0 — score 3
- **Source:** e.g. https://github.com/AminForou/mcp-gsc, https://www.pulsemcp.com/servers/gsc-mcp-server
- **Pitch:** Community Google Search Console MCP servers were broken by the 2026-07-28 MCP spec/SDK overhaul (`mcp.server.fastmcp` was removed) and have since been patched; several now expose read+write GSC access with dashboard-style output inside Claude.
- **Relevance:** `gsc-ga-creative-abrasion` currently runs as a manual scrape-and-mine loop against GSC/GA4. A working, spec-current GSC MCP server would let that loop pull live query/page data directly instead of hand-scraping the console table.
- **Suggested owner:** Signal

### 3. MCP 2026-07-28 "stateless" specification — score 3
- **Source:** https://blog.modelcontextprotocol.io/posts/2026-07-28/
- **Pitch:** An architectural redesign of MCP covering server scaling and stateless client/server negotiation — not an installable skill, but the compatibility baseline every third-party MCP server (including #1 and #2 above) is now being rebuilt against.
- **Relevance:** Explains why several previously-working community servers broke this cycle (see #2); any new MCP server evaluated for The Construct going forward should be checked against this spec version before adoption to avoid the same breakage.
- **Suggested owner:** AP

### 4. @mcpskillsio/server (mcpskills-server) — score 3
- **Source:** https://www.npmjs.com/package/@mcpskillsio/server (v2.5.2, published ~2 days before this sweep) / https://github.com/BeBraveBeKind/mcpskills-server
- **Pitch:** A pre-install "trust layer" MCP server that vets GitHub repos, npm packages, Smithery listings, and OpenClaw/Claude skills before they're added to an agent's toolchain.
- **Relevance:** Niche, but directly on-point for the discovery-sweep task itself — a lightweight vetting pass before any candidate surfaced by this weekly scan gets installed for real.
- **Suggested owner:** Cipher

### 5. WordPress MCP Adapter (core) + WPVibe plugin — score 3
- **Source:** https://developer.wordpress.org/news/2026/02/from-abilities-to-ai-agents-introducing-the-wordpress-mcp-adapter/ ; https://wordpress.org/plugins/vibe-ai/
- **Pitch:** WordPress core's own "Abilities → MCP" adapter plus a maintained plugin (WPVibe) exposing read/write/SEO/media tools over MCP to any MCP client.
- **Relevance:** Not applicable to brand9signs.com (confirmed static HTML build, not WordPress — see `b9-site-deploy`), but relevant to any client on the roster still running WordPress, where `wordpress-yoast-publishing` today is manual.
