### 1. MCP Enterprise-Managed Authorization (EMA) — now stable
**Score: 5**
**Source:** https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/
**Also:** https://claude.com/blog/enterprise-managed-auth

**Pitch:** Zero-touch OAuth for MCP servers via Okta/SSO — admins provision MCP connector access centrally; agents and users inherit it on first login with no per-app OAuth dance. Shipped stable June 18, 2026. Asana, Atlassian, Canva, Figma, Linear, Supabase, Granola already support it; Slack in progress.

**Why it matters for The Construct:** Every Construct agent that touches an MCP server currently requires per-user OAuth approval. EMA eliminates that friction across Claude Code, Claude Desktop, and Cowork in a single admin action. High-value for any onboarding or multi-agent workflow that crosses tool boundaries.

**Suggested primary owner:** Sentinel (access control / security posture)

### 3. MCP 2026-07-28 Release Candidate — Stateless Core + Tasks Extension
**Score: 4**
**Source:** https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/
**Also:** https://mcp.directory/blog/mcp-2026-07-28-release-candidate

**Pitch:** RC for the next MCP spec: stateless sessions (every request is self-contained via `_meta`), a formal extension system (reverse-DNS IDs, independent versioning), and a Tasks extension enabling long-running async work. Deployed on ordinary HTTP — no persistent connection required.

**Why it matters for The Construct:** The Tasks extension is the key win — it lets Construct agents hand off long-running jobs to MCP servers and poll asynchronously, which unblocks fire-and-forget patterns in Forge's build pipelines and Atlas's research workflows. The stateless core also simplifies hosting and scaling MCP servers internally.

**Suggested primary owner:** Architect (protocol-level design decisions)

### 5. skill-to-mcp (PyPI)
**Score: 3**
**Source:** https://pypi.org/project/skill-to-mcp/
**GitHub:** https://github.com/biocontext-ai/skill-to-mcp

**Pitch:** Python package that converts Claude Skills directories (SKILL.md + supporting files) into MCP server resources, making locally-stored skills discoverable via the Model Context Protocol by any MCP-compatible agent.

**Why it matters for The Construct:** Bridges the file-based skills world (what Construct agents author) with the protocol-based world (what other MCP clients can consume). Enables The Construct to publish its own skill library as an internal MCP resource endpoint — useful if Spectra or Signal need to pull skills dynamically rather than reading from disk.

**Suggested primary owner:** Vector (knowledge/retrieval infrastructure)
