## Candidates Scoring ≥ 3

---

### 1. agentskills-mcp
**Source:** https://github.com/zouyingcao/agentskills-mcp  
**Pitch:** Bridges Anthropic's official Agent Skills format to any MCP-compatible agent via zero-config install (`pip install mcp-agentskills`), with stdio/SSE/HTTP transport and automatic skill directory detection.  
**Score:** 5 — drop-in upgrade; WOLF's existing skills folder immediately works with Cursor, Codex, and any future MCP client without per-agent rewrites.  
**Primary owner:** WOLF

---

### 2. SkillKit MCP
**Source:** https://github.com/mk0e/skillkit-mcp  
**Pitch:** Universal portability layer that exposes skill libraries to 40+ AI coding agents (Claude Code, Cursor, Copilot, Codex) via a single MCP config entry, with Git-native versioning and remote-repo pinning.  
**Score:** 4 — Forge and Architect build skills for The Construct today; SkillKit lets those skills travel to any future agent the team adopts without re-authoring.  
**Primary owner:** Architect

---

### 3. Anthropic MCP Tunnels + Self-Hosted Sandboxes
**Source:** https://claude.com/blog/claude-managed-agents-updates  
**Pitch:** Managed Agents can now reach private internal MCP servers through an outbound-only encrypted tunnel, and execute tool calls inside customer-controlled sandboxes (Cloudflare, Daytona, Modal, Vercel) — zero inbound firewall rules required.  
**Score:** 4 — Hartley Capital's compliance posture demands data-residency guarantees; this is the first Anthropic-native path to run agents against internal APIs without exposing them to the public internet.  
**Primary owner:** Sentinel

---

### 4. skill-to-mcp (PyPI)
**Source:** https://pypi.org/project/skill-to-mcp/  
**Pitch:** Python library that reads a Claude Skill folder (`SKILL.md` + assets) and re-exports it as a live MCP server resource, enabling non-Claude agents and tools to consume existing skill definitions without porting them.  
**Score:** 3 — useful migration bridge if The Construct ever deploys a non-Anthropic agent alongside WOLF; low priority until that need arises.  
**Primary owner:** Forge

---

### 5. skillport (gotalab)
**Source:** https://github.com/gotalab/skillport  
**Pitch:** CLI + MCP daemon that manages a single canonical skill registry and serves it to any connected agent, eliminating per-agent configuration drift when skills are updated.  
**Score:** 3 — as The Construct's agent count grows, centralised skill dispatch via skillport prevents version skew across WOLF, Forge, Atlas, and future agents.  
**Primary owner:** Charlie

## Ecosystem Observation

The MCP Skills layer is converging fast: three independent projects (agentskills-mcp, SkillKit, skillport) all shipped within weeks of each other, all solving the same "one skill, many agents" problem. The ecosystem is still fragmented — no single winner — but the surface area is small enough that a lightweight evaluation sprint now prevents a costly migration later.
