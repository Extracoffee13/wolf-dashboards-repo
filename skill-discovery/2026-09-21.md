## Candidates (score ≥ 3)

### 1. MemFork — `memforkdb/memfork`
- **Source:** https://github.com/memforkdb/memfork (v0.1.0 and v0.1.1 both tagged 2026-09-21; also on PyPI as `memfork`)
- **Pitch:** "Git for AI agent memory" — an embedded in-memory store with constant-time branch/fork, three-way merge, discard, and rewind, usable from any MCP client or via function calling.
- **Score: 5** — drop-in upgrade candidate for how the swarm's agents (Vector, Forge, Signal, Cipher, Spectra, Oracle, Ledger, Atlas, Sentinel, Venture, Equity, Alpha, WOLF, Keystone, Cornerstone, Charlie, Architect) share and checkpoint working memory today; the fork/discard model maps directly onto the "try something, keep or pretend it never happened" pattern several of our skills already hand-roll (e.g. `import-memory`, `self-improving-loop`).
- **Suggested owner:** Architect

### 2. Carnet — `carnet-mcp/carnet`
- **Source:** https://github.com/carnet-mcp/carnet
- **Pitch:** An MCP gateway/broker that sits between agents and external tools, giving each caller scoped, revocable, per-identity credentials plus full audit logging and spend ceilings.
- **Score: 4** — directly addresses the credential-sprawl problem our own skills flag (vironbox-credential-routing, b9-google-api-access-setup, buzz-agent-flock's nsec/allowlist handling); would let one broker mediate access instead of each agent holding raw secrets.
- **Suggested owner:** Sentinel

### 3. jev-ultrafast-mcp — `jiawei686/jev-ultrafast-mcp`
- **Source:** https://github.com/jiawei686/jev-ultrafast-mcp
- **Pitch:** Browser-automation MCP server that runs an entire multi-step flow server-side in one tool call (ref-based element selection, deterministic assertions, macro replay) over native Chrome DevTools Protocol.
- **Score: 4** — the team leans heavily on Claude-in-Chrome/computer-use for GBP, SiteGround, and Buzz work; collapsing multi-turn browser flows into one call would cut token spend and the "tab renders blank" friction our chrome-automation skills work around.
- **Suggested owner:** Forge

### 4. secobserve-mcp — `nh4ttruong/secobserve-mcp`
- **Source:** https://github.com/nh4ttruong/secobserve-mcp (published to the official MCP Registry as `io.github.nh4ttruong/secobserve-mcp`)
- **Pitch:** Wraps SecObserve vulnerability management (triage, SBOM/scan import, VEX generation in CSAF/OpenVEX/CycloneDX) in 18 agent-facing tools with audit logging and a read-only mode.
- **Score: 3** — niche (we don't currently run SecObserve), but useful if/when the Construct needs SBOM or CVE triage for client-facing code (ANS AppBundle, B9 static site tooling).
- **Suggested owner:** Sentinel

### 5. mcp-freshness — `waseemnasir2k26/mcp-freshness`
- **Source:** https://github.com/waseemnasir2k26/mcp-freshness (v2026.09 release)
- **Pitch:** CLI that scores every MCP server in a config for liveness/maintenance freshness — does it still start and answer, how stale is the repo, is it archived — with table/JSON/shields.io badge output.
- **Score: 3** — the ecosystem now depends on a long, growing list of MCP servers (GitHub, Gmail, Drive, Higgsfield, Slack, Canva, plus whatever gets adopted from this sweep); a freshness scorer is a cheap way to catch a server going stale or getting archived before it breaks a workflow.
- **Suggested owner:** Cornerstone
