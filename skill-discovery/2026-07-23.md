## Candidates (score ≥ 3)

### 1. Claude Managed Agents — webhook coverage for environment & memory store lifecycle (score 5)
- **Source**: https://platform.claude.com/docs/en/release-notes/overview (July 22, 2026 entry)
- **Pitch**: Managed Agents webhooks now fire on four `environment.*` and three `memory_store.*` event types, so environment/memory-store state changes can be reacted to instead of polled.
- **Suggested owner**: Architect
- **Why it matters here**: The Construct already runs on webhook-driven reaction patterns (GitHub PR activity subscriptions, Praxis inbox packets). This is a direct drop-in for any agent currently polling memory-store or environment state — most notably WOLF's live-data refresh loop and Praxis's inbox watcher — and could replace scheduled polling with event-driven triggers.

### 2. Claude Managed Agents — session seeding with `initial_events` (score 3)
- **Source**: same July 22, 2026 platform release notes (platform.claude.com)
- **Pitch**: `POST /v1/sessions` now accepts up to 50 `user.message`/`user.define_outcome` initial events, starting the agent loop in the same call instead of create-then-send.
- **Suggested owner**: WOLF
- **Why it matters here**: Cuts a round trip for any script that spins up a Managed Agents session programmatically (e.g. a cron-triggered WOLF or Praxis job), simplifying automation glue code.

### 3. mcp-cli 0.20.1 (score 3)
- **Source**: https://pypi.org/project/mcp-cli/ (released July 22, 2026)
- **Pitch**: Feature-rich CLI for talking to MCP servers directly — chat mode, scripting mode, multi-provider LLM support, DAG execution plans, browser dashboard — useful for debugging any MCP server before wiring it into an agent.
- **Suggested owner**: Forge
- **Why it matters here**: Handy diagnostic tool whenever Forge stands up or debugs a new MCP integration for the C-Suite; niche (a dev tool, not an agent-facing capability) but low-cost to adopt.

### 4. MCP spec 2026-07-28 release candidate — stateless core, Extensions (Tasks/Apps), auth hardening (score 3)
- **Source**: https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/
- **Pitch**: The next MCP spec drops session IDs (stateless servers behind plain load balancers), adds an Extensions framework (server-rendered UI via MCP Apps, long-running work via Tasks), and tightens OAuth/OIDC-aligned authorization.
- **Suggested owner**: Architect
- **Why it matters here**: Not actionable yet (10-week validation window before the final spec ships), but every MCP server The Construct depends on (github, Slack, Gmail, Canva, Higgsfield, Google-Drive) will eventually need to track this migration. Worth a calendar note, not immediate work.
