# Skill Discovery Sweep — 2026-09-16

Scanned: mcp.directory, github.com (topics: claude-skill, mcp-server, anthropic-skill), npm (keywords: anthropic-skill, mcp-server), pypi (keywords: claude-skill, mcp), claude.com/blog, anthropic.com/news.

Scoring: 5 = drop-in upgrade for an existing skill · 4 = new capability the team would use weekly · 3 = niche but useful · 2 = interesting, low priority · 1 = not relevant.

Only items scoring ≥ 3 are listed (max 5).

## 1. skills-mcp — score 4

- **Source:** https://github.com/gengirish/skills-mcp (npm: `@gengirish/skills-mcp`)
- **Pitch:** An MCP server that lets any agent search, fetch, and install from a live, aggregated catalog of ~9,000 agent skills pulled from 11 GitHub sources (Anthropic, Superpowers, Composio, wshobson, antigravity, and more), refreshed on a daily build.
- **Why it matters:** This is a direct upgrade path for this exact discovery routine — instead of AP hand-scraping GitHub/npm/PyPI each cycle, an agent could query one pre-indexed catalog and get ranked, installable results.
- **Suggested owner:** AP

## 2. skillpm — score 3

- **Source:** https://dev.to/sbroenne/skillpm-package-manager-for-agent-skills-built-on-npm-3d31
- **Pitch:** A package manager for agent skills built on top of the existing npm registry, giving skills versioning, dependency resolution, and install/uninstall semantics instead of ad-hoc copy-paste.
- **Why it matters:** The Construct already runs many agents each with their own skill sets; a real package manager would make rolling out or rolling back a skill change across agents auditable instead of manual.
- **Suggested owner:** Keystone

## 3. @mcpskillsio/server — score 3

- **Source:** https://www.npmjs.com/package/@mcpskillsio/server
- **Pitch:** A "trust layer" for MCP skill packages — vets and scores third-party MCP skill packages before an agent installs them.
- **Why it matters:** As the Construct starts pulling from wider third-party skill catalogs (see #1 and #4), a vetting layer addresses the obvious supply-chain risk of installing agent instructions sight-unseen.
- **Suggested owner:** Sentinel

## 4. claude-mpm — score 3

- **Source:** https://pypi.org/project/claude-mpm/6.2.16/
- **Pitch:** A multi-agent orchestration framework layered on Claude Code — adds a skills system, MCP integration, session management, and semantic code search on top of the base CLI.
- **Why it matters:** Niche relative to the Construct's own orchestration (Hermes/WOLF), but the semantic code-search layer could be useful for agents that work directly in this and sibling repos.
- **Suggested owner:** Architect

## 5. agentic-awesome-skills (AAS Core) — score 3

- **Source:** https://github.com/CloudEngineHub/agentic-awesome-skills
- **Pitch:** A local, agent-first control plane (CLI + local MCP + catalog + "Workbench") for discovering, selecting, and validating a stack of 2,000+ agentic skills, with the selected stack recorded and reviewable.
- **Why it matters:** Useful pattern for making an agent's chosen skill stack reproducible and auditable — relevant if the Construct wants a paper trail for which skills each named agent has adopted.
- **Caveat / lower confidence:** This exact project (same description, near-identical skill counts of 2,000–2,115) is currently forked/republished under at least 8 different personal GitHub accounts (CloudEngineHub, glukicov, Linji-x, ShaunLinTW, Moshbbab, sickn33, ntxnasty-spec, FrancoStino) rather than appearing as one canonical trending repo — treat as a template being widely cloned, not independent traction, until verified further.
- **Suggested owner:** Vector
