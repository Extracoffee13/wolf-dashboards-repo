## Candidate 1 — Claude Code Dynamic Workflows

**Score: 5**
**Source:** https://claude.com/blog/introducing-dynamic-workflows-in-claude-code
**Available since:** 2026-05-28 (Claude Code v2.1.154, ships with Opus 4.8)
**Primary Owner:** WOLF

### Pitch
Claude Code now supports dynamic workflows — JavaScript orchestration scripts that Claude writes and the runtime executes, coordinating up to 1,000 parallel subagents per run — directly upgrading WOLF's orchestration ceiling and the built-in `/deep-research` command replaces the current `deep-research` skill verbatim.

### Key Details
- `ultracode` keyword or `/effort ultracode` triggers auto-workflow mode; Claude decides when to spawn a workflow per task
- Bundled `/deep-research` workflow fans out web searches, cross-checks claims via adversarial agents, returns a cited report — available on all paid plans
- Saved workflows become slash commands stored in `.claude/workflows/` (project-shared or user-local); rerunnable and inspectable
- Up to 16 concurrent agents, 1,000 total per run; subagents inherit session's tool allowlist; runs resumable within the same session
- Available on CLI, Desktop, VS Code, JetBrains, API, Bedrock, Vertex AI, Microsoft Foundry

### Construct Impact
- WOLF gains a native orchestration primitive that replaces hand-rolled multi-agent patterns
- Every agent that currently uses the `deep-research` skill gets adversarial cross-checking for free
- Workflows saved to the repo's `.claude/workflows/` become shared team infrastructure (e.g., `signal-brief`, `equity-scan`, `praxis-daily-review`)

## Candidate 2 — MCP Specification 2026-07-28 Release Candidate

**Score: 4**
**Source:** https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/
**Announced:** 2026-05-21
**Primary Owner:** Architect

### Pitch
The largest MCP protocol revision since launch makes servers stateless (no sticky sessions, plain round-robin load balancers work), ships server-rendered UIs via MCP Apps, adds a Tasks extension for long-running operations, and aligns auth with OAuth 2.0 / OpenID Connect — meaning The Construct's MCP infrastructure can scale horizontally without custom session glue.

### Key Details
- **Stateless core**: eliminates session handshakes; any HTTP load balancer handles traffic via `Mcp-Method` header routing; clients can cache `tools/list` responses per server's `ttlMs`
- **MCP Apps extension**: server-rendered UIs in sandboxed iframes — agents can surface dashboards and forms without a separate frontend
- **Tasks extension**: long-running background operations with progress events — maps directly to WOLF's async task queue model
- **OAuth/OIDC alignment**: issuer validation (RFC 9207), client registration improvements — reduces auth friction for B9S CRM and Hartley Capital data connectors
- **Formal deprecation policy**: 12-month minimum windows between deprecation and removal; safe to build against now

### Construct Impact
- Architect can plan MCP infrastructure upgrades now; RC is stable enough to prototype against
- Tasks extension directly enables stateful Praxis workflows over MCP without custom polling logic
- Stateless design unblocks horizontal scaling of the WOLF Command Center's MCP gateway

## Candidate 3 — Anthropic Agent SDK Billing Split (June 15, 2026)

**Score: 4**
**Source:** https://chatforest.com/reviews/anthropic-claude-agent-sdk-billing-split-june-15-2026-credit-pool-developer-guide/
**Effective date:** 2026-06-15
**Primary Owner:** AP

### Pitch
On June 15 Anthropic separates Agent SDK token consumption into distinct credit pools per developer namespace, enabling The Construct's multi-tenant deployment (B9S agents vs. Hartley Capital agents) to track and cap costs independently without a shared quota eating into either client's budget.

### Key Details
- Developer-managed credit pools: operators can assign budgets per agent team or client context
- Usage from `claude -p` and Agent SDK calls no longer shares the same quota as interactive sessions
- Affects all multi-tenant deployments using the Claude Agent SDK; action required before June 15 to avoid billing disruption
- Pairs with the Agent SDK's existing `max_tokens` advisor cap (also recent) to bound per-call costs

### Construct Impact
- AP must configure separate credit pools for B9S agent cluster and Hartley Capital agent cluster before the June 15 cutover
- Ledger gains clean per-client cost attribution — feeds directly into Hartley's reporting workflows
- Sentinel should verify that no agent is currently consuming from a shared pool that will be split

## Candidate 4 — @anthropic-ai/mcpb (MCP Bundles — One-Click Local MCP Install)

**Score: 3**
**Source:** https://www.anthropic.com/engineering/desktop-extensions
**npm:** https://www.npmjs.com/package/@anthropic-ai/mcpb
**Primary Owner:** Forge

### Pitch
MCP Bundles (`.mcpb`) are zip archives containing a local MCP server plus a `manifest.json`; end users install them with a single click in Claude Desktop, eliminating the current npm/npx onboarding steps that block non-technical clients from connecting to Brand 9 Signs or Hartley-specific MCP tools.

### Key Details
- `.mcpb` = zip of local server code + `manifest.json` (name, description, tool list, auth requirements)
- Single-click install in Claude Desktop; no terminal required for end users
- `@anthropic-ai/mcpb` npm package provides the build toolchain to package and sign bundles
- Lowers the barrier for B9S clients and Hartley advisors to connect to The Construct's agent tools

### Construct Impact
- Forge can package the B9S signage MCP server and Hartley data MCP server as `.mcpb` bundles for client distribution
- Reduces onboarding friction from ~10 manual steps to one click
- Cornerstone can include bundles in client-facing documentation as a first-class install path

## Candidate 5 — agentskills-mcp-server (PyPI — Skills-as-MCP Bridge)

**Score: 3**
**Source:** https://pypi.org/project/agentskills-mcp-server/
**Released:** 2026-03-05
**Primary Owner:** Keystone

### Pitch
A Python MCP server that exposes Anthropic Agent Skills as standard MCP tools and resources, letting any MCP-compatible agent (not just Claude Code) discover and invoke The Construct's skill library — useful if WOLF subagents running on non-Claude runtimes (Bedrock, Vertex) need to call shared skills.

### Key Details
- Bridges Anthropic Agent Skills format → MCP tools/resources schema
- Any MCP client (Cursor, Claude Desktop, custom agent) connects once and gets live skill catalog
- Skills auto-publish as new ones are added; no client restarts needed
- Python package; pip-installable; works with existing `~/.claude/skills/` layout

### Construct Impact
- Keystone can stand up a skills MCP server pointed at The Construct's skill library
- Non-Claude agents in hybrid pipelines (e.g., Bedrock-hosted Equity model) gain skill access without reimplementing the skill runner
- Lower priority than candidates 1–3; useful when the team expands to multi-runtime deployments
